# Шлюз

Единственный вход в систему снаружи. Проверяет токен Keycloak, извлекает
роли и личность, маршрутизирует запрос сервису-владельцу. Сервисы за ним
публичных портов не имеют.

Тонкий намеренно: вся предметная логика живёт в сервисах, иначе получился бы
распределённый монолит с ядром в шлюзе.

## Зависимости

| Пакет | Роль |
|---|---|
| [`mireacrm-common`](https://github.com/mireacrm/py-common) | настройки, метрики, трасса, ошибки |

Берётся только ядро обвяза, без дополнений: базы, брокера и gRPC у шлюза нет,
и в образ они не попадают.

## Область Keycloak

Клиенты, роли и учётные записи описаны в
[`mireacrm/deploy`](https://github.com/mireacrm/deploy) — они относятся ко всей
системе, а не к шлюзу. Конвейер забирает область оттуда и поднимает настоящий
Keycloak: интеграционный тест пропускает себя сам, когда сервер недоступен,
поэтому пропуск здесь считается провалом.

## Локально

```
pip install -e ".[dev]"
python -m pytest tests/unit -q
python -m pytest tests/integration -q   # нужен Keycloak с областью mirea
docker build -t gateway .
```

Систему целиком поднимает [`mireacrm/deploy`](https://github.com/mireacrm/deploy).
